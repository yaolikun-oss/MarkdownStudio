## Mac 上相同跨平台代码的真实界面检查

使用独立的测试 App / 用户数据目录，未替换 Mac 正式版：

- 系统打开文件、打开文件夹及文件列表点击可用。
- 约 5,000 行测试笔记在左右可视化/源码区同时显示，源码行号可见。
- 在文末实际操作左、右、上、下键；Shift+左只选中句号，Shift+上选择当前显示行的文字。
- Markdown 面板“满屏”可展开为单区，并显示“还原”；还原恢复双区。
- 系统保存面板可以保存测试笔记；首次检查发现仅设置可编辑状态也产生脏标记，已修复，并由自动测试覆盖。
- 关闭有修改的笔记，出现“保存 / 不保存 / 取消”提示；不保存能关闭。
- 恢复副本能以未命名笔记恢复，不直接覆盖原文件。
- PDF 原文显示成功，文本层可以拖选；初版自定义协议返回状态与 PDF.js 不兼容，已改为受授权的本地字节读取并复测成功。

解锁后继续实测：

- EPUB 中文原文正常显示，右键翻到第二章、左键回第一章；点击目录第二章成功；放大后显示 110%。
- DOCX 第一页标题、粗体、表格文字可见；选中第一段后，实际复制并粘贴到独立 Markdown 临时笔记成功，临时笔记随后放弃关闭。
- 发现 DOCX 工具条页数一直为 1 / 1，已在 0.1.1 修复：相同双页文档正确显示 1 / 2，点击下一页后显示 2 / 2，并可见第二页标题与内容。
- 最近使用的 Word + 笔记组合一键恢复，左右两份内容同时显示。

继续实测最终分屏处理：分隔线能获得键盘焦点；拖动与右键微调后比例为 0.6271205514，拖回后为 0.4958503306。随后切回可视化，保存的比例仍为 0.4958503306。源码满屏后工具条变为“还原”，点击后恢复左右两区。相关拖动逻辑另有 3 项自动测试。

最后的单区切换显示复测再次被系统锁屏阻断。PDF 适宽/适高、字体资源及重复段落精确定位改进完成了构建/自动检查，最终界面上尚未全部确认。

## 明确尚未验收

1. **Windows 原机执行**：本机没有可用 Windows 虚拟机/远程 Windows，未运行最终 EXE。
2. Windows 微软拼音等输入法组合输入、高 DPI、多显示器、Windows 原生文件面板、退出与重新启动。
3. 长文档精确光标定位的完整回归、单区显示与快捷键焦点切换的最终界面检查；人工的实时输入延迟基准。分屏拖动、比例保存、可视化切换后比例保持、源码满屏还原已有上述实测。
4. EPUB 与 DOCX 已有上述指定样本的界面实测；其它复杂文档与 Windows 上的界面效果仍未验收。
5. 网页真实网络导航、前进后退、收藏及剪藏，截图粘贴的最终完整用户路径。
6. Windows 安装的 LibreOffice / Calibre 实际转换；复杂 Word 分页、特殊字体、超大文档性能。

因此本产物仅作为 **Windows 0.1.3 未签名预览版**，不宣称所有功能已在 Windows 完成验收。格式支持限制、快捷键和运行方式见 README。
